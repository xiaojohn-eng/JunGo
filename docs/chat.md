# 自己的多设备会话

用户确认的范围：自己的安卓手机、Mac、Linux 服务器互发文字和文件。不增加联系人、群聊或多用户账号。

## 交互

- Android 的第五个导航入口为“会话”；外屏选择会话后全宽显示聊天，展开后可同时显示设备列表和会话。
- Mac 设置窗口增加“会话”，菜单栏可进入。文本输入、选择文件和 Finder 拖入文件均会创建真实消息/任务。
- Android 支持 `ACTION_SEND` / `ACTION_SEND_MULTIPLE`。持久 URI 可直接用于任务；临时分享授权的文件先流式保存到应用私有 outbox，避免原应用退出后失去读取权限。
- 文件卡片显示真实大小、已确认字节和状态；发送端可暂停、恢复或取消，接收端显示接收进度。收到的文件自动保存在专用收件箱，完成后才允许“另存为”。另存仍是持久任务，会校验内容；已有非空目标文件不会被静默覆盖。
- 文字显示等待连接或已送达，不伪造“已读”。设备离线时保存本地待发送消息，重连后重试；重复请求不会重复生成气泡。
- 单条文字最多 4096 个 Unicode 字符。安卓系统分享支持最多 16384 字的文字，自动分条入队，并逐条保存剩余内容；不会在 emoji 的代理项中间截断。

发送端和接收端都需要运行并保持组网连接。当前不通过第三方推送唤醒手机，也不在控制服务器暂存明文消息。手机系统终止应用后，需要在系统允许时重新运行应用/服务才能收发。

## 存储与边界

会话按设备 ID 区分；消息 ID 与内容、收发方向、设备、创建时间绑定，修订号用于接收进度更新和重试去重。

消息记录保存在设备私有 `chat/messages.json`。应用维护的 `chat-inbox` 只保存接收的文件，独立于身份密钥和传输状态。附件路径按发送设备/消息 ID 分隔，同名文件不会覆盖其他会话内容。接收端另存通过受限制的目录句柄读取，远端提供的路径不会作为任意本机路径使用。

WireGuard 私网内的 HTTPS 接口接收文字及文件卡片元数据，请求使用已配对设备身份认证。控制服务 bearer token、源文件绝对路径、Android 内容 URI 和本地传输 ID 不会进入消息协议。附件字节使用已有分块上传接口，完成 SHA-256 校验后才显示接收完成。

Mac/Linux 仍可额外选择主动共享的目录；安卓只增加会话专用收件箱，不作为任意手机文件浏览服务端。

## 本地 RPC

| 方法 | 参数 | 返回 |
| --- | --- | --- |
| `chatList` | `{}` | `{messages:[...]}` |
| `chatSendText` | `{deviceId,text}` | Message |
| `chatSendFile` | `{deviceId,source,name}` | Message，关联实际上传任务 |
| `chatSaveFile` | `{id,destination}` | Transfer，direction 为 save |
| `transferAction` | `{id,action}` | 原有任务操作，action 为 pause/resume/cancel |

Linux 也可通过 `jungo rpc --state <设备状态目录>` 使用相同接口。Message 的 path 是收件箱内相对路径，不是可直接打开的本机文件路径。UI 必须使用 `chatSaveFile`；Mac 仅在用户选择的另存任务完成后提供 Finder 显示。
